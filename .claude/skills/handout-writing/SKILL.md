# 讲义写作标准

这份技能是 2026-11-27 定稿的讲义标准，来自 11 篇学习反馈 + 四份讲义 + 11-27 的「底层重学」讨论。
完整证据和每条经验的出处见仓库根 `讲义写作经验.md`，本文件是可执行的操作版。

**写讲义的唯一目的是让学员真的学会，不是把知识讲全。**

---

## 学员画像（决定怎么写）

1. **看得懂 ≠ 写得出。** 自测题「以为会了」，动笔就卡。
2. **抽象结论记不住，具体数字和身体感觉记得住。** 力矩靠「端盘子」才通。
3. **空间想象弱。** 坐标系、姿态要用「棍子接棍子」这类图像。
4. **编程基础要从最小例子讲。** `def`、`for` 不能默认会。
5. **疑问当场跑通效率最高，攒着就烂。** 欠 11 天的 `run_epoch` 就是例子。

---

## 写作流程（每次写讲义都按这个顺序）

### 第 1 步：开写前检查（5 分钟）

1. 读 `学习路线.md` 对应课，确认这一课的范围和上一课的终点
2. 读 `进度追踪.md`，确认学员当前卡在哪、欠什么
3. 读 `learn/<课号>/` 下的代码；代码不存在就先写代码，再写讲义
4. 想清楚：**这一课在实习哪一步用、用不到什么**——用不上的枝节直接砍

### 第 2 步：所有数字和代码先在本机跑

```bash
source ~/miniconda3/etc/profile.d/conda.sh && conda activate ai
```

讲义里每个输出、每个误差、每个耗时，必须是本机跑出来的真值。
编数字是硬伤，宁可写「约」也不写假数。

### 第 3 步：按骨架写

骨架见下方「一课的骨架」。**每个代码块从 `import` 到 `print` 完整写，单独复制能跑。**

### 第 4 步：交付三件套

1. 建 `笔记/<课号>_底层推导.md` 模板（留空让学员填，不给答案）
2. 在 `进度追踪.md` 欠账表加两条（见「欠账机制」）
3. 用「交付自检清单」逐条打钩，缺一条不算交付

---

## 四步结构（每个知识点必须走完）

### 第 1 步：定义
用一句话把概念写成数学式，不写比喻。

### 第 2 步：推导
从定义走到结论，**每一步标明用了哪条定理**（链式法则、正交性、叉乘定义……）。
禁止写「这是求导的结果」「符号互换是正常现象」。读者必须能照着复现。

### 第 3 步：手算
给一组具体数字，**先笔算，再开电脑**。

### 第 4 步：验证
代码算同一组数字，两边差小于 1e-6 才算块过关。

### 分级规则

每课开头必须写一行：

```
> 笔记：`笔记/<课号>_底层推导.md`　　本课必须手推：<那一个公式>
```

- **1 个块**（本课最重要的公式）走完整四步
- **其余块**走三步：定义 → 推导 → 验证（手算可略，验证不能省）

## 三标签版式：画面 → 推导 → 手算

三个标签连着出现，中间不插别的内容。

- **【画面】**：身体感觉建立图像，不超过 5 行
- **【推导】**：从定义推到结论，每步标法则。画面到此为止
- **【手算】**：一组数，先笔算再开电脑

```
【画面】伸直手臂端盘子比贴身端累——同样的力，离转轴越远越费力。
【推导】tau = r × F。用叉乘定义：|r × F| = |r||F| sin θ。r 越长，同样的 F 产生的 tau 越大。
【手算】r = 0.5 m，F = 20 N，θ = 90° → tau = 0.5 × 20 × 1 = 10 N·m。
```

**规则**：类比结束必须直接进【推导】。禁止在类比后写「记住结论就行」。

## 一课的骨架

```
# <课号>　<标题>：解决了什么

> 预计时间　　代码路径　　笔记路径 + 本课必须手推的块

## 实习里什么时候用到它          ← 先讲用处，用不上的枝节直接砍
## 这一课要搞清楚的三件事
## 开始之前：必要的背景知识      ← 数学不够就在这补，不许跳
## 块 1：<概念 A>              ← 定义 → 推导 → 手算 → 验证
### ▶ 现在轮到你了（写笔记 · 第 N 节）   ← 每个推导块末尾都有
## 块 2：<概念 B>              ← 同上
## ...
## 代码逐段复习
## 两类坑                       ← 11.1 当场报错 / 11.2 不报错但结果错
## 动手改（2–3 个）
## 自测（答案后置，含推导）
## 一句话总结
## 下一课
```

### 「▶ 现在轮到你了」的写法

必须具体到：打开哪个文件、写第几节、算哪个数、几行、对账标准。

```
打开 `笔记/A3_底层推导.md`，写第 4 节：取 q1=30°、q2=20°，手算 J 的四个元素，
再跑 7.2 的代码对账，差 < 1e-6 才算过。
```

「思考一下」不算动作。

### 两类坑

- **当场报错的**：表格列出写法、报错原文（必须本机实测）、原因
- **不报错但结果错的**：表格列出坑、现象、检测手段

第二类每个坑必须配检测手段，只讲语法错误等于只讲一半。

## 数字和格式的硬规矩

1. **具体数字 > 文字解释**：凡是「省/费/大/小/快/慢」的结论，配两组真实数字对比
2. **路径必须真能跑**：要么本机真实路径，要么包自带示例数据；示意路径必须标注
3. **公式一律纯文本代码块对齐**，禁止 LaTeX（`\frac`、`$$`、`\begin{bmatrix}`）
4. **代码块自包含**：从 `import` 到 `print`，公共函数重复贴可以接受
5. **自测答案折叠**（`<details>`），答案里必须有推导，不能只写结论
6. **给数字目标**：例如「误差 < 1e-6」「0.6 秒到位」，讲改进时控制变量

## 笔记规则

- 每课在 `笔记/` 下建 `<课号>_底层推导.md`
- 只写学员**自己手推的过程和手算的数**，不许抄讲义
- 模板留空、留 `[ ]` 打勾位，不给答案
- 「必须手推」的那一节在模板里单独标出

---

## 欠账机制

每份讲义交付时，同步在 `进度追踪.md` 欠账表加两条：

| 内容 | 起始 |
|---|---|
| `<课号>` 底层推导笔记 N 节手推 + 对账 | 讲义交付当天 |
| `<课号>` 自测 M 题先做后看 | 讲义交付当天 |

做完在讲义节末尾打 `[对账通过]`，在欠账表划掉。
讲义是静态文档，欠账必须进表，否则会漏（11-25 的 A1 自测就是这样漏掉的）。

---

## 交付自检清单

每份讲义写完逐条打钩：

- [ ] 开头有「笔记路径 + 本课必须手推的那一个公式」
- [ ] 「实习里什么时候用到它」在最前面，用不上的枝节已砍
- [ ] 每个推导块：定义 → 推导（每步标法则）→ 手算 → 验证
- [ ] 每个推导块末尾有「▶ 现在轮到你了（写笔记 · 第 N 节）」
- [ ] 所有数字都是本机跑出来的
- [ ] 所有代码块自包含，单独复制能跑
- [ ] 所有路径本机真实存在
- [ ] 没有「记住结论就行」「不用推」
- [ ] 公式全是纯文本，没有 LaTeX
- [ ] 两类坑分开列，第二类每个坑配检测手段
- [ ] 自测答案折叠、含推导
- [ ] 笔记模板已建、`进度追踪.md` 欠账表已加两条

---

## 禁止清单

- 「记住结论就行」「不用推」
- 跳过链式法则、正交性、叉乘等步骤直接给结果
- 只给特例不给一般形式（例如只给 2 自由度平面雅可比）
- 用 LaTeX 写公式
- 代码块缺 `import` 或函数
- 讲义代码和 `learn/` 下的代码不一致又不说明
- 编造数字、假路径、没跑过的输出

---

## 验收标准

一课算讲完，要同时满足：

1. 学员能不看讲义，手推出核心公式
2. 手算的数和代码输出对得上（差 < 1e-6）
3. 能说出公式在实习哪一步用、用错了会怎样
4. 笔记里有对应的手推记录
5. `进度追踪.md` 里本课两条欠账已划掉

五条全中才算过。少一条，这一课就还是「看懂」，不是「学会」。
