## 第 1 步：最短的仿真程序

在 `learn/A1_仿真循环/` 下新建一个文件 `A1_1.py`，用 VS Code 打开，**手敲**下面这 15 行。
每完成一步，就把代码贴进 `A1_1.py` 保存一次，最后这个文件就是完整程序。

```python
import mujoco

xml = """
<mujoco>
  <worldbody>
    <geom type="plane" size="5 5 .1"/>
    <body pos="0 0 2">
      <freejoint/>
      <geom type="box" size=".2 .2 .2"/>
    </body>
  </worldbody>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(xml)
data = mujoco.MjData(model)

for i in range(1000):
    mujoco.mj_step(model, data)

print(data.qpos)
```

保存后按 `Ctrl+F5` 运行（或点右上角 ▶）。你屏幕上大概率会看到这样一堆东西：

```
[-1.14048851e-17  1.03391527e-16  1.99892245e-01  1.00000000e+00
  3.29505451e-17  7.88568931e-19  4.48731361e-21]
```

**先别慌，这个就等于 `[0, 0, 0.2, 1, 0, 0, 0]`。**
为什么长得这么吓人，看下面「输出为什么是 7 个数」和「那一堆 e-17 是什么」。

### 逐行看

**`import mujoco`**
导入物理引擎。MuJoCo = Multi-Joint dynamics with Contact，就是"带接触的多关节动力学"。

**`xml = """..."""`**
一个字符串，描述场景。MuJoCo 用 XML 描述模型，这个格式叫 MJCF。
它没有存在文件里，是直接写在代码里的——真实项目里会写成 `.xml` 文件再加载。

**`<worldbody>`**
"世界"的容器。所有东西都放在这里面。可以理解成场景的根节点。

**`<geom type="plane" size="5 5 .1"/>`**
一个平面，长宽各 5 米。这是**地面**。`geom` 是几何体，是"看得见、能碰撞"的东西。

**`<body pos="0 0 2">`**
一个刚体，放在世界坐标 `(0, 0, 2)`，也就是离地面 2 米高。

**`<freejoint/>`**
自由关节。作用：让这个刚体可以在空间中自由平移和旋转（不受约束）。
没有关节的 body 是焊死在世界上的，不会动。

**`<geom type="box" size=".2 .2 .2"/>`**
这个刚体是一个边长 0.4 米的立方体（`size` 是半边长）。

**`model = mujoco.MjModel.from_xml_string(xml)`**
把 XML 解析成模型。`model` 是**只读的静态描述**：有几个关节、多重、有没有电机。建好之后不再变。

**`data = mujoco.MjData(model)`**
创建运行时数据。`data` 是**会变的状态**：每个关节当前的角度、速度。初始时全是 0。

**`for i in range(1000): mujoco.mj_step(model, data)`**
推进 1000 步仿真。默认每步 0.002 秒，1000 步 = 2 秒仿真时间。
每一调用 `mj_step`，引擎就按物理定律算出下一步的状态。

**`print(data.qpos)`**
`qpos` = position，所有位置状态拼成的一个数组。

### 输出为什么是 7 个数

把 7 个数一一对应上：

```
[-1.14e-17  1.03e-16  1.9989e-01  1.00e+00  3.30e-17  7.89e-19  4.49e-21]
     x          y         z           qw        qx        qy        qz
```

自由关节有 **7 个**位置量：

- 前 3 个是位置 `x, y, z`
- 后 4 个是姿态四元数 `w, x, y, z`

z 从 2 变成 0.1999，是因为方块边长 0.4 米，掉到地上后中心离地 0.2 米。

四元数是 `1, 0, 0, 0`，表示没有旋转（A2 课会专门讲四元数）。

### 那一堆 e-17 是什么

x、y 本该是 0，为什么打印出来是 `-1.14e-17`？

计算机存小数用的是 **float64**，原理是"尾数 × 2 的幂"。像 0.2、0.4 这种十进制小数，写成二进制是**除不尽的**（跟 1/3 写成 0.333... 一个道理），所以每次加减都会在末尾几位上留一点误差。

`1e-17` 等于 0.00000000000000001，比原子核的尺度还小一百亿倍——**物理上就是 0**。

`1.99892245e-01` 就是 0.199892245 米，跟 0.2 的差也是同一个来源。你以后跑仿真会一直见到这种数，习惯就好。

### 想让输出好看一点（可选）

在文件开头加两行：

```python
import numpy as np
np.set_printoptions(precision=4, suppress=True)
```

`precision=4` = 保留 4 位小数；`suppress=True` = 太小的小数不要用科学计数法，直接显示 0。

加完再跑，输出变成：

```
[-0.      0.      0.1999  1.      0.      0.      0.    ]
```

**这一步不用真的加**，知道有这回事就行。后面讲义要打印数值时，一律用 `f"{x:.4f}"` 这种格式化写法，不依赖全局设置。

## 第 2 步：看它怎么掉下来的

上一步只看了最终结果。加几行，看过程：

```python
import mujoco

xml = """
<mujoco>
  <worldbody>
    <geom type="plane" size="5 5 .1"/>
    <body pos="0 0 2">
      <freejoint/>
      <geom type="box" size=".2 .2 .2"/>
    </body>
  </worldbody>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(xml)
data = mujoco.MjData(model)

for i in range(400):
    mujoco.mj_step(model, data)
    if i % 100 == 0:
        print(f"第 {i+1:3d} 步，高度 {data.qpos[2]:.4f} 米")
```

输出：

```
第   1 步，高度 2.0000 米
第 101 步，高度 1.8018 米
第 201 步，高度 1.2113 米
第 301 步，高度 0.2283 米
第 401 步，高度 0.1997 米
```

### 这段时间里发生了什么

- **第 1 到 100 步**：只掉了 0.2 米。因为速度从 0 开始，越掉越快
- **第 100 到 200 步**：掉了 0.6 米，明显加速
- **第 300 步左右**：掉到地面（0.2 米是方块中心的高度）
- **之后**：停住不动。地面挡住了它

**你用眼睛看到的这两秒物理，是引擎每 2 毫秒算一次、算了 1000 次的结果。**

```python

```

`%` 是取余。每 100 步打印一次，不然 1000 行输出没法看。

## 第 3 步：把方块换成"挂在关节上的杆"

现在把自由关节换成**铰链关节**（hinge）。改 XML：

```python
import mujoco
import numpy as np

xml = """
<mujoco>
  <worldbody>
    <body pos="0 0 1.2">
      <joint type="hinge" axis="0 1 0"/>
      <geom type="capsule" fromto="0 0 0 0 0 -0.5" size="0.03"/>
    </body>
  </worldbody>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(xml)
data = mujoco.MjData(model)

print("nq =", model.nq, "  nv =", model.nv)

data.qpos[0] = 1.0        # 手动给它一个初始角度

for _ in range(500):
    mujoco.mj_step(model, data)

print("500 步后角度:", round(data.qpos[0], 4), "弧度 =",
      round(np.degrees(data.qpos[0]), 2), "度")
print("当前角速度:", round(data.qvel[0], 4))
```

输出：

```
nq = 1   nv = 1
500 步后角度: 0.272 弧度 = 15.58 度
当前角速度: 4.8887
```

### 改了什么

**`<joint type="hinge" axis="0 1 0"/>`**
铰链关节：只能绕一个轴转。`axis="0 1 0"` 表示绕 y 轴转。
换个说法：这是一个"合页"，杆只能在这个合页上前后摆。

**`<geom type="capsule" fromto="0 0 0 0 0 -0.5" size="0.03"/>`**
胶囊体，从原点 `(0,0,0)` 到 `(0,0,-0.5)`，半径 0.03。
就是一根长 0.5 米、朝下挂着的杆子。

**`nq` 从 7 变成 1**
因为铰链关节只有 1 个自由度（转的角度）。自由关节是 7 个（3 位置 + 4 姿态）。
`nq` = 位置量个数，`nv` = 速度量个数。单摆这两个都是 1。

**`data.qpos[0] = 1.0`**
手动把初始角度设成 1 弧度（约 57 度）。不设的话杆竖直向下，正好是平衡位置，它不会动。

### 关键观察：它在摆，停不下来

- 500 步后角度 15.58 度
- **角速度 4.8887 rad/s**，还在飞快地转

因为没有阻尼。重力势能变成动能，再变回去，来回摆，永远不会停——这就是理想单摆。

真实机器人有电机可以主动控制，下一节加电机。

## 第 4 步：给关节装一个电机

在 XML 末尾加一段 `<actuator>`：

```python
import mujoco
import numpy as np

xml = """
<mujoco>
  <worldbody>
    <body pos="0 0 1.2">
      <joint name="hinge" type="hinge" axis="0 1 0"/>
      <geom type="capsule" fromto="0 0 0 0 0 -0.5" size="0.03"/>
    </body>
  </worldbody>
  <actuator>
    <motor joint="hinge" ctrlrange="-50 50"/>
  </actuator>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(xml)
data = mujoco.MjData(model)

print("nu =", model.nu)

for i in range(500):
    data.ctrl[0] = 10.0      # 一直给 10 牛·米的力矩
    mujoco.mj_step(model, data)

print("500 步后角度:", round(data.qpos[0], 3), "弧度 =",
      round(np.degrees(data.qpos[0]), 1), "度")
```

输出：

```
nu = 1
500 步后角度: 34.862 弧度 = 1997.4 度
```

### 改了什么

**`<joint name="hinge" .../>`**
给关节起了个名字。电机要靠名字找到它——**没名字就先加名字，否则会报 `unknown transmission target`**，我写讲义时被这个坑了一次。

**`<actuator>` + `<motor joint="hinge" ctrlrange="-50 50"/>`**
装一个电机，接在 hinge 关节上，输出力矩范围 -50 到 50 牛·米。
`actuator` 就是"驱动器"，现实里是电机、液压缸之类。

**`model.nu` 从 0 变成 1**
`nu` = number of controls，控制量的个数。有几个电机就是几。

**`data.ctrl[0] = 10.0`**
每个时间步都要给控制量。这里固定给 10 牛·米。

### 关键观察：2000 度

500 步 = 1 秒仿真时间，转了 1997 度，大约 5 圈半。

**因为恒定力矩一直在做功，而没有任何东西让它减速。** 这就是"开环控制"——只给力，不看结果。转成什么样全凭物理。

机器人不可能这么控制。下一步加反馈。

## 第 5 步：写第一个控制器（PD）

现在让它在**竖直向上**的位置停住。竖直向上对应角度 `pi`（180 度）。

```python
import mujoco
import numpy as np

xml = """
<mujoco>
  <worldbody>
    <body pos="0 0 1.2">
      <joint name="hinge" type="hinge" axis="0 1 0"/>
      <geom type="capsule" fromto="0 0 0 0 0 -0.5" size="0.03"/>
    </body>
  </worldbody>
  <actuator>
    <motor joint="hinge" ctrlrange="-50 50"/>
  </actuator>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(xml)
data = mujoco.MjData(model)

KP = 80.0
KD = 8.0
TARGET = np.pi          # 目标角度：竖起来

for i in range(4000):
    # 1. 读当前状态
    q = data.qpos[0]
    qd = data.qvel[0]

    # 2. 算误差，归一到 [-pi, pi]
    err = (TARGET - q + np.pi) % (2 * np.pi) - np.pi

    # 3. 算力矩
    data.ctrl[0] = np.clip(KP * err - KD * qd, -50, 50)

    # 4. 推进仿真
    mujoco.mj_step(model, data)

    if i in (0, 20, 50, 100, 200, 400):
        print(f"第 {i+1:4d} 步: 角度 {np.degrees(data.qpos[0]):8.1f} 度, "
              f"力矩 {data.ctrl[0]:7.2f}")

print("最终角度:", round(np.degrees(data.qpos[0]), 2), "度")
```

输出：

```
第    1 步: 角度     -0.1 度, 力矩  -50.00
第   21 步: 角度    -19.8 度, 力矩  -50.00
第   51 步: 角度    -90.0 度, 力矩   19.83
第  101 步: 角度   -152.1 度, 力矩    7.35
第  201 步: 角度   -177.3 度, 力矩    0.69
第  401 步: 角度   -180.0 度, 力矩    0.01
最终角度: -180.0 度
```

### 这 4 行就是所有机器人控制器的骨架

```python
q = data.qpos[0]                                       # 读状态
err = (TARGET - q + np.pi) % (2*np.pi) - np.pi         # 算误差
data.ctrl[0] = np.clip(KP*err - KD*qd, -50, 50)        # 算力矩
mujoco.mj_step(model, data)                            # 推进一步
```

**读状态 → 算误差 → 算输出 → 推进**。这四个动作，从单摆到 30 个自由度的人形机器人，一模一样。
以后你看到的所有控制器（MPC、强化学习策略都一样）都是这个循环，区别只在"算输出"那一步怎么算。

### 为什么力矩一开始是 -50

第 1 步时角度是 0 度，目标 180 度，误差 `pi`，`KP * pi = 80 * 3.14 = 251`。
远超限幅 50，所以被 `np.clip` 卡在 -50（方向朝负数那边转）。

**这解释了为什么它是甩上去的**：前 20 步一直满力矩，杆被甩起来了。

### KD 在干什么

```python
KD * qd
```

角度转得越快，这一项的反向力越大。它是刹车。

去掉它会怎样？下一节实验。

### 为什么最后停在 -180 而不是 180

角度是循环的，-180 度和 +180 度是**同一个位置**（竖直向上）。
代码里的归一化公式在边界返回 `-pi`，所以显示成 -180。不是 bug。

## 第 6 步：三个实验，验证你的理解

每次只改一个参数，跑完看输出，**先猜结果再跑**。

### 实验 A：把 KP 改成 1.0

```python
KP = 1.0
```

**先猜**：它还能上去吗？

**再看**：跑到 4000 步也停在 **-39.8 度**，离目标 180 度差得远。
**原因**：它被重力压在下面附近，`KP * 误差` 产生的力矩顶不过重力（倒立时需要约 2.45 牛·米，而这里只有 1 倍误差的量级），推不上去。

### 实验 B：把 KD 改成 0

```python
KD = 0.0
```

**先猜**：没有刹车会怎样？

**再看**：跑 1000 步后角度变成 -2832 度，一直在转。
**原因**：只有弹簧没有阻尼，系统能量不衰减，永远振荡。

### 实验 C：把目标改成 90 度（水平）

```python
TARGET = np.pi / 2
```

**再看**：停在 **87.3 度**，不是 90 度，差 2.7 度。
**原因**：这就是 PD 的**稳态误差**。水平位置重力力矩最大（1 米长的杆，重力矩约 4.9 牛·米），PD 要靠 `KP * 误差` 产生反向力矩去顶住它，所以必须留一点误差才能平衡：`80 * 误差 ≈ 4.9`，误差 ≈ 0.06 弧度 ≈ 3.5 度，和实测的 2.7 度对得上（杆的质量分布让实际重力矩略小）。

把 KD 从 8 调到 1 再看：最终依然停在 87.3 度，因为**稳态误差只跟 KP 有关，跟 KD 无关**；但中间会晃很久才停，因为 KD 小、阻尼小。

**这是纯 P 控制的通病**。要消除稳态误差，通常加一个积分项变成 PID，或者用前馈补偿重力。人形机器人上一般不靠 PID 硬顶，而是用 RL 策略学出补偿——C 模块会讲。

## 第 7 步：组装成完整程序（加窗口）

前面都是无窗口跑。现在把全部拼起来，加可视化：

```python
import time
import mujoco
import mujoco.viewer
import numpy as np

xml = """
<mujoco>
  <option gravity="0 0 -9.81" timestep="0.002"/>
  <worldbody>
    <light pos="0 1 3" dir="0 -1 -1"/>
    <geom type="plane" size="5 5 0.1" rgba="0.35 0.35 0.40 1"/>
    <body pos="0 0 1.2">
      <joint name="hinge" type="hinge" axis="0 1 0"/>
      <geom type="capsule" fromto="0 0 0 0 0 -0.5" size="0.03"
            rgba="0 0.7 1 1" mass="1"/>
    </body>
  </worldbody>
  <actuator>
    <motor joint="hinge" ctrlrange="-50 50"/>
  </actuator>
</mujoco>
"""

model = mujoco.MjModel.from_xml_string(xml)
data = mujoco.MjData(model)

KP, KD, TARGET = 80.0, 8.0, np.pi

with mujoco.viewer.launch_passive(model, data) as viewer:
    while viewer.is_running():
        err = (TARGET - data.qpos[0] + np.pi) % (2 * np.pi) - np.pi
        data.ctrl[0] = np.clip(KP * err - KD * data.qvel[0], -50, 50)

        mujoco.mj_step(model, data)
        viewer.sync()
        time.sleep(1 / 240)
```

新增的三样：

- **`<option timestep="0.002"/>`**：每步 2 毫秒，和默认值一样，写出来是为了让你知道在哪改
- **`<light>` 和 `rgba`**：光照和颜色，纯视觉，不影响物理
- **`launch_passive`**：开窗口。`viewer.sync()` 把最新状态刷到画面，`time.sleep` 控制刷新率（只影响看着舒不舒服，不影响物理）

不用查讲义：

1. `MjModel` 和 `MjData` 的区别？谁在变？

### 参考答案

<details>
<summary>1. MjModel 和 MjData 的区别？谁在变？</summary>

- `MjModel`：编译后的**静态**模型，存不变的东西——质量、几何尺寸、重力、timestep、关节类型。建好后只读不改。
- `MjData`：**运行时状态**，存每一步都在变的东西——`qpos`、`qvel`、`qacc`、`ctrl`、接触力。

**在变的是 `data`。** 例：`model.nq` 永远是 1；`data.qpos[0]` 从 0 一路变到 -3.14。

分开的好处：一份 `model` 可以同时喂给几百个 `data` 并行仿真（强化学习里一次跑上千个环境靠的就是这个）。

</details>

<details>
<summary>2. nq 和 nv 为什么单摆是 1、自由方块是 7 和 6？</summary>

`nq` 是**位置坐标的个数**，`nv` 是**真正的自由度个数**。两者只在姿态上不同：

| 关节 | nq | nv | 原因 |
|---|---|---|---|
| hinge 单摆 | 1 | 1 | 一个角度，一一对应 |
| slide 滑轨 | 1 | 1 | 一个位移，一一对应 |
| ball 球窝 | 4 | 3 | 姿态用 4 个数的四元数记 3 个转动自由度 |
| freejoint 自由方块 | 7 | 6 | 3 个位置 + 4 个姿态；速度是 3 平动 + 3 转动 |

差的 1 个是**姿态**：四元数多用 1 个数，换掉欧拉角的万向节死锁。所以 `qpos` 有 7 个，`qvel` 只有 6 个。

</details>

<details>
<summary>3. 为什么电机必须靠 name 找到关节？</summary>

因为 `<actuator>` 写在 `<worldbody>` **外面**，它和关节隔着层级，既没有共享的坐标，也不能按“第几个”去数（世界里有 body、geom、light，顺序不稳）。**唯一的引用方式就是点名。**

```xml
<joint name="hinge" .../>              <!-- 被点名的关节 -->
<motor joint="hinge" .../>             <!-- 按名字找过去 -->
```

忘了写 `name`，实测报错 `Element name '', id 0`——MuJoCo 不知道 `joint="hinge"` 指的是谁，连模型都建不起来。

</details>

<details>
<summary>4. PD 的 P 和 D 分别解决什么问题？</summary>

- **P（比例）解决“推不动”：** 离目标越远，出力越大。只有 P 时，腿像一根弹簧，冲到目标、冲过头、再弹回来，**永远振荡**（实测 KD=0：角度 0 → 1.81 → 3.96 → 5.58 → 6.26……停不下来）。
- **D（微分）解决“停不下”：** 速度越快，反向刹车越狠。实测 KD=8 时 0.6 秒收住、几乎无超调。

一句话：**P 负责到得了，D 负责停得下。**

</details>

<details>
<summary>5. 为什么误差要做 `(x + pi) % (2*pi) - pi` 的归一化？</summary>

因为关节没有限位，`qpos` 可以无限增长（转很多圈）。直接相减会得到“绕远路”的错误误差。

实测：`TARGET = π`、`q = 7.0`（已经转过一圈多）：

```
直接相减：π - 7.0 = -3.858   ← 超出 [-π, π]，算错
归一化后：(π - 7.0 + π) % 2π - π = 2.425   ← 正确，还差 2.425 弧度
```

归一化就是把任意角度折回 **[-π, π]**，保证算的永远是“最近的那条路”。这个操作叫**角度回绕（wrap）**，以后写四元数、写航向角会反复用到。

</details>

<details>
<summary>6. timestep 从 0.002 改成 0.001，跑 4000 次，仿真时间变长还是变短？控制器表现会变吗？</summary>

**仿真时间变短**：4000 × 0.001 = 4 秒（原来 4000 × 0.002 = 8 秒）。

**控制器表现基本不变**：PD 公式里没有 `dt`，它只关心“差多少、多快”。步长变小，只是每步更细。实测到达 -170 度：

```
dt = 0.002  → 146 步，0.292 秒
dt = 0.001  → 291 步，0.291 秒
dt = 0.0005 → 581 步，0.290 秒
```

步数翻倍，**物理时间几乎不变**。真正会变的是极端情况：步长太大（如 0.05）会数值不稳定，实测最终冲到 -206 度、来回振荡。

结论：`dt` 决定“每步走多久”，不决定“控制器好不好”；太小浪费算力，太大仿真会炸。

</details>
