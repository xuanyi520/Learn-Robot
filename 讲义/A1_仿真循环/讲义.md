## 二、MuJoCo 里的三个对象

一个仿真程序永远只有三个东西：

| 对象 | 是什么 | 谁改它 |
|---|---|---|
| `MjModel` | 模型的静态描述：有几个关节、质量多少、有没有电机 | 一开始建好，之后不再变 |
| `MjData` | 运行时状态：每个关节的角度 `qpos`、速度 `qvel`、控制量 `ctrl` | 每步仿真在变 |
| `viewer` | 看向 `MjData` 的窗口 | 只读，不改 |

**关键区分**：模型只读，数据在变。你写代码时绝大部分时间在跟 `data` 打交道。

```python
model = mujoco.MjModel.from_xml_string(XML)   # 静态
data = mujoco.MjData(model)                    # 动态，初始全 0
```

## 三、仿真循环到底在干嘛

核心只有两行：

```python
data.ctrl[0] = 力矩        # 1. 你决定给多少力
mujoco.mj_step(model, data) # 2. 物理引擎推算下一步状态
```

`mj_step` 每次推进一个 `timestep`。本例里 `timestep="0.002"`，也就是每步 2 毫秒。跑 4000 步就是 8 秒仿真时间。

`mj_step` 内部按顺序做四件事：

1. 读 `ctrl`，算出每个关节受到的力
2. 算加速度（牛顿-欧拉）
3. 积分出新的 `qvel` 和 `qpos`
4. 处理接触、约束

**你只需要管第 1 步**。后面全交给引擎。

这就是整个机器人控制的本质：**每个时间步，根据当前状态算出一个控制量，交给物理引擎。**

## 四、状态与控制

本例的模型只有一个 hinge 关节，所以：

| 数据 | 维度 | 含义 |
|---|---|---|
| `data.qpos[0]` | 1 | 关节角度，单位弧度。0 = 杆朝下，pi = 杆朝上 |
| `data.qvel[0]` | 1 | 关节角速度，单位 rad/s |
| `data.ctrl[0]` | 1 | 电机输出力矩，单位 N·m，限幅 ±50 |

真实人形机器人是这套东西乘以 30：30 个关节就有 30 个 `qpos`、30 个 `qvel`、30 个 `ctrl`。

**为什么机器人里角度用弧度不用度？** 因为所有运动学公式（三角函数、雅可比）都默认弧度，转来转去只会多一次乘法，还容易错。

## 五、PD 控制器为什么能稳住

代码里的控制律就这一段：

```python
err = (target - q + np.pi) % (2 * np.pi) - np.pi   # 角度误差，归一到 [-pi, pi]
data.ctrl[0] = kp * err - kd * qd                   # 位置项 - 速度项
```

拆成两项看：

**第一项 `kp * err`（比例项）**：离目标越远，推得越用力；正好在目标时推力为 0。

**第二项 `-kd * qd`（微分项）**：动得越快，反向拉得越狠。相当于阻尼，防止冲过头。

这就像你用手扶一根倒立的棍子：

- 歪了就往回推（比例）
- 快倒了就提前用力刹（微分）

**为什么要做角度归一化？** 单摆在 359 度时，离目标 180 度只差 179 度，但直接相减得 -179 再取绝对值也是 179——等一下，这个例子不直观。真正的场景是目标在 0 度、当前在 359 度：直接相减得 -359，看起来要转一大圈；归一化后是 1 度，转一小步就行。**角度是循环的，直线距离会算错。**

## 六、四个增益的实测对比

下面是我在你这台机器上跑出来的真实数据（同样跑 4000 步）：

| kp | kd | 最终角度 | 最后 1000 步的波动范围 | 结论 |
|---|---|---|---|---|
| 0.5 | 0.1 | -31.8 度 | [-31.9, -31.7] | 推不动，卡在半路 |
| 2.0 | 0.5 | -117.9 度 | [-117.9, -117.9] | 还是推不到顶 |
| 80 | 0 | 7575 度 | [5643, 7575] | 一直在转，没有阻尼 |
| 80 | 0.5 | -180.0 度 | 稳定 | 成功 |
| 80 | 8 | -180.0 度 | 稳定 | 成功 |

三个结论：

1. **kp 太小，力矩不够克服重力**。倒立时重力矩约 2.45 N·m，kp 必须让 `kp * pi > 2.45` 才可能稳在顶部。
2. **kd 不能为 0**。没有微分项就是纯弹簧，会一直振荡甚至转起来。
3. **-180 度和 180 度是同一个位置**。代码里目标写 `np.pi`（180 度），实际停在 -180 度——因为归一化在边界返回 -pi。这不是 bug。

## 七、代码逐段

```python
XML = """..."""                        # 模型描述：关节、几何、电机
model = mujoco.MjModel.from_xml_string(XML)
data = mujoco.MjData(model)
```

从字符串建模型，省去外部文件。真实项目里通常从 `.xml` 或 `.urdf` 文件加载，例如：

```python
model = mujoco.MjModel.from_xml_path("robot.xml")
```

```python
def controller(model, data, kp=KP, kd=KD, target=TARGET):
```
注意这里把 `model` 也传进来了，虽然本例没用。真机上控制器要读 `model` 里的关节限位、质量，先养成习惯。

```python
while viewer.is_running():
    controller(model, data)
    mujoco.mj_step(model, data)
    viewer.sync()
    time.sleep(1 / 240)
```
`viewer.sync()` 把最新状态刷到窗口。`time.sleep` 控制刷新率——**只影响你看着舒不舒服，不影响物理**，物理的时间步由 `timestep` 决定。
