## 第 1 步：IK 就是解一个方程

A3 的结论：

```
末端速度 = J @ 关节速度
```

现在反过来问：想让末端移动 `err`（一个 2 维向量），关节该动多少 `dq`？

把"速度"换成"这一步的增量"，就是解方程：

```
J @ dq = err
```

2 连杆、2 个方向，J 是 2x2 方阵，理论上：

```
dq = J^-1 @ err
```

直接求逆行不行？**在非奇异位形可以，在奇异位形 J 不可逆，直接算就炸。** 这就是 A3 实验 4 看到的 `det(J) = 0`。

代码里的做法（先看结论，下一节讲为什么加 `lam`）：

```python
def dls_step(q, target, lam):
    err = target - fk(q)                     # 想让末端往哪走
    J = jac(q)                               # 2x2 雅可比
    dq = J.T @ np.linalg.solve(J @ J.T + lam**2 * np.eye(2), err)
    return dq, err
```

形状走一遍：

```
J        (2, 2)
J @ J.T  (2, 2)
+ lam^2 I (2, 2)
err      (2,)
solve 出来 (2,)   -> 再乘 J.T (2, 2) -> dq (2,)
```

### 实测：10 次迭代到微米

起点 `[0.3, -0.5]`，末端在 `(-0.029, -0.581)`，目标 `(0.2, -0.4)`：

```
第  1 次迭代  误差 291.702297 毫米  关节增量 1.76824
第  2 次迭代  误差 182.139606 毫米  关节增量 0.79600
第  3 次迭代  误差  40.134743 毫米  关节增量 0.11711
第  4 次迭代  误差   3.554218 毫米  关节增量 0.01765
第  5 次迭代  误差   0.258707 毫米  关节增量 0.00136
第 10 次迭代  误差   0.000001 毫米  关节增量 0.00000
```

**收敛是指数级的**：每次迭代误差大约掉一个数量级。

为什么是指数级？因为雅可比是"局部"线性近似——离目标越远，线性近似越不准，第一步只走了大约 2/3；越近越准，最后几步是纯牛顿法的速度。

## 第 2 步：为什么加阻尼

`lam` 这一项，就是 A3 自测第 5 题问的"阻尼"。

### 2.1 定义

```
dq = J^T @ (J @ J^T + lam^2 I)^-1 @ err
```

- `J` 是 2×2 雅可比，`err` 是末端位置误差（2 维），`dq` 是这一步的关节增量
- `lam` 是标量，量纲和雅可比相同（这里都是 1，无量纲）
- 这个式子叫**阻尼最小二乘**（DLS, damped least squares）

### 2.2 推导：这个公式从哪来

**目标**：解 `J dq = err`。J 接近奇异时不能直接求逆，所以改成"允许差一点，但限制 dq 别太大"。

【画面】J 接近奇异 = 两个关节的作用方向几乎重合。末端要往某个方向走，两个关节只能往同一方向出力，怎么分配都是猜——数学上就是方程无解，或者解无穷大。阻尼的做法：允许方程欠一点，换关节增量别太大。

【推导】不直接解方程，改成求一个**最小二乘问题**：

```
最小化 f(dq) = ||J dq - err||^2  +  lam^2 ||dq||^2
                └─ 解方程的偏差 ─┘   └─ 关节增量的大小 ─┘
```

第一项要求尽量满足 J dq ≈ err，第二项惩罚 dq 过大。对 dq 求导令零：

```
第 1 项求导：2 J^T (J dq - err)        ← 用 d||Ax-b||^2/dx = 2 A^T (Ax-b)
第 2 项求导：2 lam^2 dq                ← 用 d||x||^2/dx = 2x
两式相加令零：J^T (J dq - err) + lam^2 dq = 0
整理：        (J^T J + lam^2 I) dq = J^T err
解出：        dq = (J^T J + lam^2 I)^-1 J^T err      ← 标准形式
```

**等价性证明**（一行）：

```
两边同乘 (J^T J + lam^2 I) 和 (J J^T + lam^2 I)：
(J^T J + lam^2 I) J^T = J^T J J^T + lam^2 J^T = J^T (J J^T + lam^2 I)
所以 (J^T J + lam^2 I)^-1 J^T = J^T (J J^T + lam^2 I)^-1
```

**为什么 lam 能防爆**：`J J^T` 接近奇异时最小特征值接近 0；加 `lam^2 I` 后，所有特征值变成 `sigma_i^2 + lam^2`，最小也不低于 `lam^2`，求逆时分母不再接近 0。

import numpy as np

np.set_printoptions(precision=6, suppress=True)

L1 = L2 = 0.3
q1, q2 = np.radians(30), np.radians(20)


def jac(q1, q2):

    s12, c12 = np.sin(q1 + q2), np.cos(q1 + q2)
    return np.array([[-L1 * c1 - L2 * c12, -L2 * c12],
                     [ L1 * s1 + L2 * s12,  L2 * s12]])


J = jac(q1, q2)
lam = 0.05
err = np.array([0.1, 0.05])

dq = J.T @ np.linalg.solve(J @ J.T + lam**2 * np.eye(2), err)
dq0 = J.T @ np.linalg.solve(J @ J.T, err)        # lam = 0（可逆时能算）

### 2.4 实测：lam 不是越小越好

同一个起点、同一个目标，只换 lam：

```
lam=0.01  ->  末端 [-0.31, 0.04]   误差 674.0818 毫米
lam=0.05  ->  末端 [0.2, -0.4]     误差 0.0000 毫米
```

lam 更小反而发散了。原因：这个姿态接近奇异，J 的逆把误差放大成大跳，一步跳过目标，下一跳又跳回来，来回打转。

**lam 要和雅可比本身的大小配合。** 这里的 J 元素量级是 0.3~0.6，lam 取 0.05 大约是 J 的 1/10；取 0.01 太小，压不住。

实际工程里的调法：

- lam 从大到小扫，看误差曲线什么时候开始抖
- 或者自适应：`lam` 随 `det(J)` 变小而变大（接近奇异时自动加重阻尼）

## 第 3 步：多解——末端固定，姿势有两种

同一目标，换三个起点：

```
起点 [0.3, -0.5]  ->  解 [ 0.266, -1.459]
起点 [-0.2, 0.8]  ->  解 [-1.193,  1.459]
起点 [1.0, -1.5]  ->  解 [ 0.266, -1.459]
```

末端误差都是 0。但关节角分成两组：一组解"肘部朝下"（q2≈-1.46），一组解"肘部朝上"（q2≈+1.46）。

**这就是 IK 的多解性**：末端位置只约束 2 个自由度，但对 2 连杆来说已经刚好满秩——解不出"第三种姿势"，只是有两种镜像。

真实机器人自由度更多，解更多。所以工程上必须加**附加条件**选解：

- 离当前姿势最近（最小化关节角变化）
- 不撞关节限位
- 不撞自己（肘部保持某个方向）
- 能量最小

**迭代法天然会选"离起点最近"的那个解**，这就是为什么 IK 的初始姿势很重要——初始给错，会收敛到一个奇怪的姿势。

## 第 4 步：画圆——跟踪轨迹 = 每帧解一次 IK

现在让末端沿圆走：

```python
center = np.array([0.0, -0.35])
radius = 0.15
for k in range(n_steps):
    theta = 2 * np.pi * k / n_steps
    target = center + radius * np.array([np.cos(theta), np.sin(theta)])
    for _ in range(20):          # 每个目标点迭代 20 次
        dq, err = dls_step(q, target, lam=0.01)
        q = q + dq
```

这里 lam 用 0.01 也能收敛，因为整条圆都不经过奇异点——**lam 的大小只在奇异附近才要命**，这和实验 1、3 的结论一致。

实测 120 个点：

```
平均跟踪误差 3.92e-17 米
最大跟踪误差 1.62e-16 米
实测路径半径 0.1500 米
```

误差是浮点噪声级——因为圆完全在可达范围内，也不经过奇异点。

**工程上的对应**：机器人走路时，足端轨迹是规划好的（比如一段摆线），每一步都要对参考位置解一次 IK 得到关节角。如果参考轨迹经过了不可达或者接近奇异的区域，IK 就会开始给出奇怪的关节角——**这正是 B2「重定向为什么会出错」的根源**：人体动作里有些位置，机器人腿根本够不到，IK 只能"尽力而为"，结果就是脚滑或者脚抖。

## 第 5 步：够不到，以及速度爆炸

目标 `(0, -1)`，离原点 1 米，但臂展只有 0.6 米：

```
lam=0.001   200 次后末端 [-0.000, -0.600]   误差 400.00 毫米
lam=0.05    200 次后末端 [ 0.030, -0.599]   误差 402.15 毫米
```

两个 lam 都停在伸直位（末端 z ≈ -0.6），误差就是"够不到的那 400 毫米"。

注意这里代码里加了 `np.clip(dq, -0.1, 0.1)`——每步最多转 0.1 弧度。**不加限幅，小 lam 会让关节一步跳几弧度，200 次后关节转到几百弧度，位置完全失控**（可以注释掉试一次，验证这句话）。

### 速度爆炸：奇异点附近最危险

在快伸直的位置，让末端往上抬 10 厘米：

```
q2=-60 度  ->  单步关节增量 0.6 rad
q2=-30 度  ->  单步关节增量 1.2 rad
q2=-10 度  ->  单步关节增量 3.8 rad
```

越接近伸直，同样的末端位移需要越大的关节转动。这就是 A3 自测第 5 题的答案：**加阻尼之后这个数会变小**，因为 `lam^2 I` 把分母撑住了。

## 第 6 步：用 mink——工程里的标准工具

手写 DLS 能跑，但缺三样东西：关节限位、多任务加权、和 MuJoCo 的完整集成。`mink` 就是干这个的。

### 本机的一个坑

mink 默认求解器是 `quadprog`，**本机没装，必须显式写 `solver="daqp"`**：

```python
velocity = mink.solve_ik(
    config, [task], dt,
    solver="daqp",      # 本机只有 daqp，不写就报 ModuleNotFoundError
    damping=1e-3,
    limits=limits,
)
```

直接照抄 mink 官方文档会报 `No module named 'quadprog'`，这不是代码错，是环境里只装了 daqp。

### 三个核心对象

```python
config = mink.Configuration(model)          # 当前构型，内部持有 q 和 data
task   = mink.FrameTask("tip", "site",      # 要追的目标：某个 site 的位置
                        position_cost=1.0,
                        orientation_cost=0.0)
task.set_target(mink.SE3.from_translation(np.array([x, 0.0, z])))
```

- `Configuration`：存关节角，`config.q` 直接读写
- `FrameTask`：一个"任务"，追某个 frame 的位姿。**`position_cost` 是权重**，0 表示不管
- `SE3.from_translation`：构造一个只有平移的目标位姿（3D，平面任务把 y 填 0）

循环三行：

```python
velocity = mink.solve_ik(config, [task], dt, solver="daqp", limits=limits)
config.integrate_inplace(velocity, dt)
mujoco.mj_forward(model, config.data)
```

`solve_ik` 解的是一个**二次规划（QP）**，把多个任务的加权误差和限位约束一起解掉。这就是为什么它能同时处理"追到手"和"别超限位"。

## 第 7 步：零空间——末端不动，肘部自己挪

2 连杆追 2 维位置是"满秩"的，末端一定，两个关节就全定了，没有多余的自由度。

换 3 段杆（3 关节，总长 0.8 米），追末端 2 个坐标：多出 1 个自由度。

```python
Jpinv = J.T @ np.linalg.inv(J @ J.T + 0.005**2 * np.eye(2))   # 3x2 的伪逆
dq = Jpinv @ e                                                # 主任务
dq = dq + (np.eye(3) - Jpinv @ J) @ (-0.5 * (q - q_posture))  # 零空间姿态
```

`np.eye(3) - Jpinv @ J` 叫**零空间投影**：任何向量乘上它，都变成"不影响末端位置"的分量。

实测两种跑法，末端都到 `(0, -0.55)`：

```
只用末端任务：        关节 [0.984, -1.228, -0.844]   误差 0.000 毫米
末端任务 + 零空间：   关节 [1.107, -1.563, -0.294]   误差 0.003 毫米
```

**末端位置一模一样，关节角完全不同。** 多出来的那 1 维自由度被拿去满足姿态要求了。

### 这和机器人什么关系

人形机器人 30 多个关节，走路时脚的位置只有 6 个约束（每只脚 3 个位置 + 3 个姿态，支撑脚固定时更多），**剩下二十多个自由度全是零空间**。

这就是为什么：

- 同样把脚踩在同一个位置，有的机器人走得好看，有的走得歪——零空间里的姿态任务不一样
- 公司会专门写"姿态正则项"（上身保持直立、手臂自然下垂），本质就是往零空间里塞任务
- mink 的 `PostureTask` 就是干这个的

| 写法 | 报错原文 | 原因 |
|---|---|---|
| `mink.solve_ik(...)` 不写 `solver="daqp"` | `ModuleNotFoundError: No module named 'quadprog'` | mink 默认用 quadprog，本机只装了 daqp |

| 坑 | 现象 | 检测手段 |

## 代码逐段（`learn/A4_数值IK/A4_1.py`）

```python
dq = J.T @ np.linalg.solve(J @ J.T + lam**2 * np.eye(2), err)
```

用 `np.linalg.solve` 而不是 `np.linalg.inv`：先求逆再乘，数值上更不稳、更慢。求解线性方程组就够了。

```python
J_mj = jacp[[0, 2], :]
```

（这是 A3 的写法，A4 用的是手写 `jac`，方便内层循环里反复用。工程上追性能时，内层循环用解析雅可比，外层校验用 MuJoCo。）

```python
dq = Jpinv @ e + (np.eye(3) - Jpinv @ J) @ (-0.5 * (q - q_posture))
```

零空间公式。注意这里的 `0.5` 是姿态增益，太大零空间运动会震荡，太小则收敛慢。`-0.5*(q - q_posture)` 就是"朝姿态目标方向走的增量"。

### 参考答案

<details>
<summary>1. IK 为什么没有闭式解（不能直接写公式）？</summary>

因为正运动学里有关节角的 **sin/cos**，反解就变成解三角方程组。2 连杆两段时还能推出公式（高中几何），但：

- 关节一多，方程次数暴涨，公式写不出来
- 有多个解，公式也表达不了"选哪个"
- 真实机器人带关节限位、避碰，这些约束没法写进一个公式

所以工程上统一用**迭代**：从当前姿势出发，每步算一次雅可比、走一小步，逼近目标。

迭代的另一个好处：**天然延续**——上一帧的解就是这一帧的起点，所以连续跟踪时关节角不会乱跳。

</details>

<details>
<summary>2. 阻尼最小二乘里 lam 太大、太小分别会怎样？</summary>

- **太小**：接近奇异时 `J J^T` 接近奇异，求逆把误差放大成大跳。实测 lam=0.01 时误差 674 毫米、来回打转（lam=0.05 时收敛到 0）。
- **太大**：`lam^2 I` 把所有方向都压制，末端慢慢爬向目标，收敛很慢，而且精度变差（到不了精确位置）。

合适的 lam 大约是雅可比元素量级的 1/10。工程上常用自适应：`det(J)` 越小，`lam` 越大。

</details>

<details>
<summary>3. 为什么同一个末端位置会有多组关节角？实机怎么选？</summary>

2 连杆的末端位置只约束了 2 个数，但"肘部朝左"和"肘部朝右"都能到同一个点——实测两组解：

```
[0.266, -1.459]  和  [-1.193, 1.459]
```

实机的选择方式：

- **离当前姿势最近**（迭代法天然如此）
- **不超关节限位**（ConfigurationLimit）
- **避碰**（mink 的 CollisionAvoidanceLimit）
- **零空间姿态任务**（PostureTask，让多余的关节保持自然姿势）

GMR 重定向时，不同初始姿势会给出不同的机器人姿态，所以 GMR 里会有"参考姿势"这个输入。

</details>

<details>
<summary>4. 画圆实验里误差 3.92e-17 米，说明什么？换成真实机器人，误差会是这样吗？</summary>

说明在**这个理想模型里**（无噪声、无延迟、无接触、无限精确的雅可比），DLS 能收敛到浮点精度。

换成真实机器人，误差会来自：

- 关节编码器噪声（角度读数不准）
- 传动误差（卓益得是绳驱，电机转角和关节角之间有偏差）
- 雅可比用的是"理想几何"，实际连杆长度有公差
- 控制周期内的目标在动

真实 IK 的跟踪误差是毫米级甚至厘米级，不会是 1e-17。**仿真里看到 1e-17 要意识到这是"模型完美"的结果，不是算法本身这么神。**

</details>

<details>
<summary>5. 零空间投影 `I - J^+ J` 作用在向量上，结果有什么性质？</summary>

对任意向量 `v`，令 `u = (I - J^+ J) v`，那么：

```
J @ u = J @ v - J @ J^+ @ J @ v = J @ v - J @ v = 0
```

也就是 `J @ u = 0`——**u 引起的末端速度为零**。

所以零空间是"满足 J dq = 0 的所有 dq 组成的空间"，维度 = 关节数 - 末端约束数。3 关节 2 约束时是 1 维；人形 30+ 关节时是二十多维。

实测：加了零空间项后，末端误差 0.003 毫米（比纯主任务的 0.000 略大），但关节角完全不同——这点误差是姿态项和主任务在软约束下的折中。

</details>

<details>
<summary>6. mink 和手写 DLS 的关系是什么？为什么要用 mink？</summary>

**关系**：mink 的核心就是我们实验 1 写的阻尼最小二乘，外面套了一层二次规划（QP）。

实测两者画同一个圆，误差都是浮点噪声级，完全一致。

**为什么要用**：

- **关节限位**：手写版不管 q 会不会超范围，mink 的 `ConfigurationLimit` 会
- **多任务加权**：末端任务 + 姿态任务 + 避碰，一起解
- **和 MuJoCo 集成**：`Configuration` 直接持有 `MjModel`/`MjData`
- **维护成本**：自己手写容易在奇异、限位、多任务交界处出 bug

学这一课的意义：知道 mink 内部在干嘛，出问题时能定位到"是雅可比算错了，还是 lam 不合适，还是零空间在捣乱"。

</details>

## 一句话总结

**IK 没有公式，只能从当前姿势出发一小步一小步逼近；每步用 `dq = J^T (J J^T + lam^2 I)^-1 err` 把末端误差换成关节增量，lam 防奇异爆炸；末端定住的姿态不止一种，剩下的自由度（零空间）用来摆好看的姿势。**
